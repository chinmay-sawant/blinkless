# blinkless 0.0.1

0.0.1 is the renderer cut. HTML and CSS go in. A drawing list comes out.
A drawing list is the ordered set of paint operations a host program draws
on its own canvas. This tree does not write a PDF file, does not encode a
page as PNG or JPEG, and does not ship a `blinkless` command.

The history on `master` is 54 commits, `23061d8` through `c085b34`, dated
2026-10-08 through 2026-10-13. There is no git tag. The per-commit ledger is
[commits.md](commits.md).

The first commit is not a small library written from scratch. `23061d8`
imports the previous product in one snapshot: module
`github.com/chinmay-sawant/gowkhtmltopdf`, status v0.2.6, two command
binaries, an `internal/pdf` writer, a page image encoder, a frontend site,
and the 0.1.0 through 0.2.7 plan trees. 2,627 files. The rest of 0.0.1 is
that tree with the writer, the page encoder, the commands, and the site
removed, then repaired and extended as a drawing-list engine.

## What you call

```text
HTML + CSS -> parse -> style -> layout -> drawing list
```

`html.Parse` reads the document. `css.Apply` applies stylesheets. `WidthPx`
and `HeightPx` must both be greater than 0, or `css.Apply` returns
`ErrBadSize` (`css/css.go` line 113).
`layout.DisplayList` returns `*layout.Display`. `display.Order` is paint
order. `display.Ops` is source order. Operation coordinates are canvas
points, y down. Text Y is the baseline. Element boxes, and the canvas width
and height, are CSS pixels, y down. One CSS pixel is 0.75 points because
the engine uses 96 CSS pixels per inch and 72 points per inch.
`Display.PointsPerPixel` is 72/96. `Display.PixelPerPoint` is 96/72. Those
two fields were swapped once, in `a9381bf`, and the names now match the
ratios.

The module path is `github.com/chinmay-sawant/blinkless`. Direct modules are
`github.com/go-text/typesetting` for OpenType shaping and
`github.com/tdewolff/canvas` for SVG rasterization. The default build is
`CGO_ENABLED=0`.

Package comment: `doc.go`. The same pipeline is the opening of `README.md`.

## Layout changes

Early repairs, before the coverage waves:

- An invalid declaration does not replace a valid one.
- `@supports` treats `and(`, `or(`, and `not(` as functions.
- Flex `justify-content` keeps `gap` and distributes only leftover free space.
- `fr` grid tracks share free space.
- `line-height: normal` uses the face ascent, descent, and line gap, in whole CSS pixels.
- Root and body margins collapse, including a nonzero body margin.
- Flex items enclose floats.
- `text-wrap-style: balance` bisects the line width. `pretty` came later.
- Absolutely positioned root and body boxes anchor to the initial containing block, the rectangle the page is laid out in.
- A border shorthand with no width is `medium`, 3 CSS pixels, 2.25 points. Explicit `0` stays 0. `thin` is 1 CSS pixel. `thick` is 5.

`layout.SnapDisplayToDevicePixels` copies a display list and changes only
positive stroke widths on stroked rectangles and lines. The device scale
factor is how many screen pixels sit in one CSS pixel. The function snaps
those stroke widths onto that grid. A hairline stays at least one device
pixel. Coordinates, boxes, text, fills, images,
links, and groups stay exact. A nil display returns `ErrNilDocument`. A
NaN, infinite, or non-positive scale returns `ErrBadDeviceScale`. Layout
itself does not snap. Screen callers opt in. Commit `6892dc5` records that
eight Chrome comparison cases stayed blocked because boxes remain in points,
and that at device scale 1 the painted border widths matched for 38 of 38
joined bordered elements. No later commit on `master` says those eight cases
were closed.

Wave G engine changes, `8533431`:

- Grid `align-content` shifts row tracks when the container height is definite.
- `tab-size` applies on the paint fast path, so a tab is no longer one glyph wide there.
- `border-image-repeat` tiles edge middles and clips a trailing partial tile. It no longer stretches those middles.
- `text-justify` can turn justification off, keep inter-word gaps, or spread slack across characters.
- `white-space-trim` drops edge blank breaks before line layout.

Wave H, `e2bbb31`: inline SVG stroke dash, offset, line cap, line join, and
miter limit are baked into the PNG of that SVG image operation. They are not
separate stroke operations on the drawing list. `list-style-image` inherits
from `ul` to `li`. Container-query rows were promoted on tests of a two-pass
evaluation that already existed.

Ruby, `77c7afe`: `ruby-align`, `ruby-merge`, `ruby-overhang`, and
`ruby-position` place annotations on the inline line. `clip-rule: evenodd`
can punch the center of a twice-wound star clip. `string-set`, bookmarks,
and footnotes have Go helpers in that commit and do not become running
headers, outline operations, or a footnote area. Footnote content stays in
normal flow.

Wave L limits that are easy to miss:

- `break-before` and `break-after` values `column` and `page` can force the next multicolumn column. They do not start a new page.
- `color-scheme: dark` paints an opaque `#121212` canvas and dark default text. An author background still wins.
- `forced-color-adjust` maps toward system colors only when forced-colors mode is on. The switch is `Options.ForcedColorsActive`.
- `scroll-margin` is stored. Production paint does not scroll. The scroll offset stays zero unless a test sets it.
- `transform-box: view-box` needs an SVG box in the walk. An inline `<svg>` is one raster image, so a plain HTML path often sees no difference.
- `font-variation-settings`, `font-optical-sizing`, and `font-palette` change the used face on the vendored variable font and the color-palette demo font. A static face does not diverge.

Wave M, `64dc880`, is the commit whose subject says "3D, fragmentation and
wide-gamut". In this engine those words mean the following.

3D is a flatten onto a 2D matrix. `internal/layout/transform_3d.go` keeps
the paint pipeline 2D. `rotateX`, `rotateY`, `rotateZ`, `rotate3d`,
`translateZ`, `scaleZ`, `perspective()`, and `matrix3d` parse onto a side
channel. At stamp time the matrix is projected and written as a 2D transform
on the operations. `perspective` on an ancestor foreshortens that bake.
`transform-style: preserve-3d` multiplies matrices before the one flatten.
`backface-visibility: hidden` drops a box's own operations when the flattened
facing sign is negative. There is no depth buffer.

Fragmentation here is column breaks inside one drawing list. `orphans` and
`widows` move content between columns. Widow line count is
`round(height / line-height)`, not a walk of real line boxes. `text-wrap-style`
values `pretty` and `avoid-short-last-line` rebreak lines in the pack loop.
`break-inside` stays partial, as above.

Wide gamut means color channels may be stored outside 0..1.
`css.ParseColorWide` accepts `color()`, `lab()`, `lch()`, `oklab()`,
`oklch()`, `hwb()`, and wide `color-mix()`. `dynamic-range-limit: standard`
and `constrained-high` fold channels into 0..1. `no-limit` and `high` keep
the headroom on the used color, so a text operation can carry those floats.
There is no HDR framebuffer and no wide-gamut image encode.

## Masks

PR #5, commit `30971e1`, merged as `c085b34` on 2026-10-13.

Ten standard properties: `mask`, `mask-image`, `mask-mode`, `mask-position`,
`mask-size`, `mask-repeat`, `mask-origin`, `mask-clip`, `mask-composite`,
`mask-type`.

Eight aliases: `-webkit-mask`, `-webkit-mask-image`, `-webkit-mask-position`,
`-webkit-mask-size`, `-webkit-mask-repeat`, `-webkit-mask-origin`,
`-webkit-mask-clip`, `-webkit-mask-composite`. `mask-mode` and `mask-type`
have no alias. Legacy composite keywords map `source-over` to `add`,
`source-out` to `subtract`, `source-in` to `intersect`, and `xor` to
`exclude`.

There is no mask operation kind. A masked element is a group. `BlendGroup`
carries `Mask *MaskDescriptor`. Group edges are marker operations. Callers
tell them apart with `IsGroupBegin`, `IsGroupEnd`, and `GroupBoundary`.
The marker kind paints nothing. WASM group JSON adds optional `mask.layers`.
Image bytes sit in the shared image table.

An external SVG `<mask>` fragment can be rasterized to an alpha PNG by
`svg.RasterizeMask`. The layer then says it is preprocessed, and the host
uses that alpha directly. The raster side is capped at 4096 pixels.

The host composites the pixels. Blinkless attaches the layer data. Direct
image sources use alpha. Position, size, repeat, origin, clip, and composite
travel as tokens for the host to resolve. Out of the wave: CSS gradients as
mask images, `image-set()`, mask-border painting, the
`-webkit-mask-box-image*` names, and in-repo pixel replay. Catalog status
for these 18 names is partial.

## Drawing-list JSON

WASM `Convert` accepts `html`, `mode` set to `display`, `width`, and
`height`. Older writer fields are rejected. The document schema is
`blinkless.drawinglist/1` (`bindings/wasm/drawing_list.go`). Units for
operation geometry are points. Canvas width and height are CSS pixels.
The payload includes `ops`, `order`, `boxes`, `groups`, `fonts`, and
`images`. Font and image bytes are base64, keyed by id. Mask layers, when
present, hang off `groups`.

`layout.DisplayList` skips the raster budget, so a canvas too large to
rasterize can still return a list. That sentence is the Unreleased note in
`CHANGELOG.md`. The masking fields are newer than that changelog section.
